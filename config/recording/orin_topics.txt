# orin_topics.txt — topics recorded by golfcart-record.service on the ORIN.
#
# One topic per line. `#` starts a comment, blank lines are ignored. Read by
# scripts/recording/record_unit_exec.sh, which passes them to `ros2 bag record`.
#
# Topic names verified against a running ZED X on 2026-08-07. They follow the
# zed-ros2-wrapper v5 scheme (rgb/color/rect/image), NOT the v4 scheme
# (rgb/image_rect_color) that docs/design/multi_machine_deployment.md quotes.
#
# WHY THE ORIN RECORDS SEPARATELY: the ZED is cabled to the orin, and only its
# *compressed* stream (~5 MB/s) would fit across the shared 100 Mb/s LAN at all
# — the raw stream is ~276 MB/s. Recording it here, onto the orin's own disk,
# keeps the LAN free for the master's two LiDARs (~30 MB/s each), which are
# cabled to the master and recorded there.
#
# LIDAR_HOST (config/sensors.conf, master_topics.txt) can move the LiDAR
# drivers here instead. The three topics below are commented out because that
# is NOT the default and, today, not even a real option: each raw LiDAR is
# ~30 MB/s and the master<->orin link is the same shared 100 Mb/s LAN the ZED
# note above describes, so two LiDARs plus the ZED does not fit either
# direction across it. See docs/roadmaps/8-lidar-on-orin.md. If LIDAR_HOST is
# ever set to orin over a link that can carry it, uncomment these three and
# comment out their twins in master_topics.txt.
#
# Depth is off: depth.depth_mode is NONE in golfcart_sensor_kit_launch's
# config/zed.param.yaml, so nothing publishes
# on the depth topics. Enable both deliberately if ever needed — depth data is
# very large.
